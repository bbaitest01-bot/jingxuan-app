執行「回報」流程。**全程唯讀：不修改任何檔案、不執行任何會改變狀態的指令。**

模式：參數為 `$ARGUMENTS`。有參數（人類 / AI / 雙軌）直接輸出；無參數則用 AskUserQuestion 讓使用者選 👤 給人類看 / 🤖 給 AI 看 / 🚀 雙軌都要；無法互動時預設人類模式。

共通要求：
- 只依實際程式碼、`git diff` 與實際驗證結果撰寫；每個成果與檔案標註 `[已驗證]`、`[未驗證]` 或 `[待部署]`（依賴 Supabase migration / Edge Function 部署者）。
- 微型拆解四階段中不適用者標 `[不適用]`，不得硬湊。

**👤 人類模式**：一句話成果摘要 → 四階段進度 → 變更檔案清單（含驗證標籤）→ 👁️ 手動體驗旅程（操作路徑、預期畫面、Toast 提示）→ 下一步建議（可否收工）。

**🤖 AI 模式**：輸出單一 ```markdown 代碼區塊，內含：
- 安全邊界：🔒 唯讀檢查，禁止部署、套用 migration 或修改正式資料庫；🛡️ 不輸出任何 API Key、Token、密鑰或個資；🚫 缺測試帳號/環境變數/權限時標 `[無法驗證]`，不得猜測通過。
- 改動檔案與架構上下文、Happy Path 驗收清單、邊界找碴清單（空值、超長字串、連點防抖、競態、RLS 越權、雙向副作用）、P0/P1/P2 回報格式。

**🚀 雙軌**：先人類模式，文末附完整 AI 模式代碼區塊。
