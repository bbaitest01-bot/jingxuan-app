---
執行「開工」流程（本步驟只讀，不修改任何檔案；唯一例外是第 4 步使用者同意認領時，只改 `待做清單.md` 那一列）。文件在 `../jingxuan-vault`。

1. **前置安全檢查**：在本專案與 `../jingxuan-vault` 各執行 `git status`。若有未提交變更，或目前在尚未收工合併的特徵分支，先發出警示，請使用者先 「收工」(`/finish`) 或確認後再繼續。
2. **確認身分**：用 AskUserQuestion 讓使用者點選：蘿蔔 (lobo)、巨獸 (beast)、沛沛 (peihan)、小陳 (chen)。
3. **巡檢新靈感（唯讀）**：掃描 `../jingxuan-vault/0X_*_工作區/想法存放區/`，若有尚未出現在 `進度.md` 的新想法，詢問是否摘要提報到 `進度.md` 萬能收件匣（不得修改原始筆記）。
4. **展示待辦**：讀取 `../jingxuan-vault/進度.md` 與 `../jingxuan-vault/問題修復/待做清單.md`，用 AskUserQuestion 讓使用者點選要做的事。
   - 待做清單只列「狀態＝待做、認領人空白」的項目；「暫緩」區不列。
   - 選單一次最多 4 個選項：依「口試前要做 → 待確認 → 之後做」的順序列前 3 項，第 4 個選項是「看其他項目」（再列下一批，或請使用者直接打編號）。
   - **認領**：選到待做清單的項目時，用 AskUserQuestion 問「要認領這一項嗎？」。同意 → 只把 `待做清單.md` 那一列的狀態改「進行中」、認領人填第 2 步選的身分，並給一段 vault 提交訊息（Summary：`docs: 認領 <編號>`），請使用者在 GitHub Desktop 提交 vault main 並 Push，完成後才進入第 5 步。不同意 → 回到選單。
   - 認領後讀該項目的修復工作單（原因、解法、測試編號）作為本次任務；工作單的解法是建議，實作時發現要改，就更新工作單並在「結果」寫原因。
5. **影響力評估**：讀取 `../jingxuan-vault/03_蘿蔔_工作區/想法存放區/專案全景地圖_草稿.md`，列出此任務會牽連的其他模組與角色權限（雙向）。
6. **微型拆解**：拆成 `(1) Schema/RLS → (2) Service 邏輯層 → (3) UI 元件 → (4) 驗證` 的小票；不適用的階段標 `[不適用]`。
7. **分支建議**：建議 `feature/<身分英文>-<功能>`（例：`feature/lobo-customer-list-ui`），並提供 GitHub Desktop 建立分支的步驟。經使用者同意才由 AI 執行 git 指令。
